GUIDES & REFERENCE

Platform documentation

How sessions, workers and security work.

01 · Pairing

Enter a valid international phone number. The server creates a real Baileys socket and requests a WhatsApp pairing code. Complete linking in WhatsApp's Linked devices screen.

02 · Session security

The Session ID is a random reference, not the WhatsApp credential. Authentication files are snapshotted, encrypted with AES-256-GCM and stored in PostgreSQL. Raw auth files are never sent to the browser.

03 · Deployment

A deployment starts a separate worker process with a private temporary authentication directory. The worker restores your encrypted auth state and runs the original bot source.

04 · Hosting

Use a paid, always-on Render web service with PostgreSQL. This initial process supervisor runs workers as child processes on the same service instance. Keep the service at one instance unless you move workers to a distributed queue.

05 · Revocation

Stop the bot, revoke the session in this dashboard, then remove the linked device from WhatsApp. Revocation deletes the encrypted authentication snapshot from the platform database.

06 · Existing features

The original plugins, lib utilities and data modules are retained. Some original plugin messages still contain the source project's former branding and need a separate content review.

HELP CENTER

Support & status

Troubleshooting for JAVIEL MD platform users.

Common issues

Pairing code did not arrive?

Check the country code, ensure the phone is online and retry after the current request expires.

Session restores but bot is offline?

Check deployment logs. A session may have been logged out or the worker may have failed to load an original dependency.

Deployment stays in preparing?

Confirm the Render service is always-on, PostgreSQL is reachable and the worker logs show session restoration completed.

Need to disconnect?

Stop the deployment, revoke the session here, and remove the linked device in WhatsApp.
